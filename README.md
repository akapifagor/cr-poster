# CR offers -> Telegram канал

Следит за новыми офферами Content Rewards (все форматы и ниши) и постит их в канал с твоего аккаунта (юзербот, поэтому работают кастомные эмодзи). Картинка поста - баннер оффера.

## Как работает
- `post.yml` - одна длинная задача GitHub Actions: каждые `poll_seconds` (60 c) опрашивает CR и сразу постит новые офферы. Через `loop_minutes` (5,5 ч) сама запускает следующую задачу, так что опрос идёт без перерывов, в том числе после падения или отмены. Задержка от появления оффера до поста ~1-2 минуты.
- Чтобы остановить постер, отключи workflow «CR offers -> Telegram» и «Watchdog» во вкладке Actions: отмена запуска его не остановит, следующий стартует сам.
- `watchdog.yml` - запускается сразу после окончания каждого запуска постера и по расписанию (GitHub выполняет такое расписание лишь несколько раз в сутки). Перезапускает постер, если цепочка оборвалась. Если постер упал в первые 10 минут, сразу не перезапускает, чтобы сломанный код не крутился по кругу.
- Несколько новых офферов сразу уходят с интервалом `post_gap_minutes` (3 мин) через отложенные сообщения Telegram, без спама. Интервал считается от реальной отправки, так что и после паузы от Telegram (FloodWait) посты не идут подряд.
- Раз в `refresh_every_minutes` (2 ч) бот сверяет посты за последние `refresh_hours` (72 ч) с CR. Если рекламодатель поменял ставку, лимит за пост, порог просмотров, бюджет, лимит постов или включил заявку, пост пересобирается со строкой «🔄 Условия обновлены ДД.ММ». Если оффер на паузе или закрыт, под заголовком появляется «⛔ Оффер на паузе» или «⛔ Оффер закрыт», а если он снова открылся, пометка снимается. За проход не больше `refresh_max_edits` (8) правок, подписчикам уведомления не приходят.
- Новый оффер = активный публичный оффер, которого нет в `seen.json`. Офферы, выложенные больше `max_age_hours` (48 ч) назад или потраченные на `max_spent_pct` (80%), молча пропускаются.
- `seen.json` коммитится сразу после каждой публикации. При старте бот сверяется с последними постами и отложенными сообщениями канала, поэтому даже при потерянном коммите оффер не уйдёт дважды.
- При 3 ошибках подряд бот пишет в «Избранное» твоего аккаунта (не чаще раза в час).

Публичный репозиторий: минуты Actions бесплатны и без лимита. В приватном цикл 24/7 съест бесплатные 2000 мин/мес примерно за 6 часов.

## Запуск на GitHub (без VPS), ~10 минут
1. my.telegram.org -> API development tools -> создай приложение, возьми api_id и api_hash.
2. На своём компьютере: `pip install telethon` и `python login.py`. Введи api_id, api_hash, номер и код из Telegram. Скрипт выведет TG_SESSION.
   TG_SESSION = полный доступ к твоему аккаунту. Никому не отправляй, храни только в GitHub Secrets.
3. Загрузи файлы в репозиторий на GitHub (включая .github/workflows).
4. Репозиторий -> Settings -> Secrets and variables -> Actions -> New repository secret: TG_API_ID, TG_API_HASH, TG_SESSION (и GEMINI_API_KEY, см. ниже).
5. В config.json впиши "channel": "@твой_канал" (твой аккаунт должен быть админом с правом публикации).
6. Actions -> "CR offers -> Telegram" -> Run workflow. Первый запуск запомнит все текущие офферы и запостит 3 последних для проверки (first_run_post). Дальше работает сам.

Одна сессия Telegram не должна работать на двух машинах одновременно (Telegram может её отозвать), поэтому все workflow с Telegram (post, edit, emoji) стоят в одной очереди `poster`: постер уступает очередь и перезапускается после них. Не запускай `main.py` локально, пока работает постер.

## Кастомные эмодзи соцсетей
Отправь себе в Избранное одно сообщение с премиум-эмодзи в порядке X, TikTok, Instagram, YouTube и запусти workflow "Emoji ids". Полученные id попадут в config.json -> platform_emoji. Пока пусто - стоят обычные 𝕏 🎵 📸 ▶️.

## Рефка
Когда CR одобрит партнёрку, впиши в config.json "link_template", например
"https://contentrewards.com/c/campaigns/{id}?ref=КОД" (формат возьмём из твоей партнёрской ссылки).

## Что в посте
Название, ниша, формат (клиппинг / UGC с лицом / без лица...), готовый футаж (оценка по описанию оффера, точный список материалов в брифе), ставки по каждой соцсети с лимитом за пост и порогом оплаты, гео-ставки флагами стран (например «$2.00, кроме 🇧🇩🇮🇳🇵🇰» или «$2.00 🇲🇽🇦🇷, остальной мир не оплачивается»), условия пула (сколько просмотров нужно, чтобы попасть в выплату), лимит постов на креатора, бюджет и % потраченного, по заявке или нет, рекламодатель (галочка CR, число активных кампаний, сколько клипперам уже начислено в них), ссылка.

## Нейросеть для ниш и футажа (Gemini, бесплатно)
1. aistudio.google.com -> Get API key -> создай ключ.
2. GitHub Secrets: добавь GEMINI_API_KEY.
3. Actions -> "AI test (no posting)" -> Run workflow. Скрипт прогонит 50 офферов с ручной разметкой и в конце лога напишет точность AI и правил. Ничего не постит.
Ответ Gemini ограничен схемой: ниши и формат только из фиксированных списков (`NICHES`, `FORMATS` в main.py), игра отдельным полем ("Игры: GTA 6"). Заметка про футаж проходит чистку (единый стиль, без искажённого «футаж»).
Модели: config.json -> ai_model (основная) и ai_fallback_model (если у основной кончилась дневная квота, она тормозит или недоступна). Сейчас gemini-3.1-flash-lite (футаж верно 45/49 на тесте) и gemini-3.5-flash-lite (42/50). gemini-3.5-flash на бесплатном тарифе не подходит: медленная и квота ~несколько запросов в день. Если у всех моделей кончилась квота, пост собирается по правилам.
Сравнить модели: Actions -> "AI test (no posting)" -> поле model.

## Обновить старые посты
Actions -> "Re-render old posts" -> Run workflow: пересобирает подписи последних N постов по текущим данным офферов (без уведомлений подписчикам). Посты с офферами, которых уже нет в активных, не трогает.

## Настройки (config.json)
`poll_seconds` - частота опроса, `loop_minutes` - длина одной задачи (до 350), `post_gap_minutes` - интервал между постами, `max_per_run` - сколько офферов ставить в очередь за один опрос, `max_age_hours`, `max_spent_pct`, `first_run_post`. Обновление постов: `refresh_every_minutes` (0 = выключено), `refresh_hours`, `refresh_max_edits`, `refresh_edit_gap_seconds`.

## Тесты
`python -m unittest discover -s tests -v` - офлайн-тесты на реальных данных CR (tests/fixtures.json) и на цикле публикации с фейковым Telegram.
`python main.py --dry` - показать посты, которые ушли бы сейчас, ничего не отправляя.
